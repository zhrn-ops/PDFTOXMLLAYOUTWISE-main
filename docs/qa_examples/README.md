# Synthetic generated report examples

These files were generated by the independent evaluator from
`tests/fixtures/qa/synthetic.v1.json`. All source material is synthetic. They
demonstrate evaluator arithmetic and regression detection, not real-world
scientific conversion accuracy or publisher-schema validity.

| Variant | Evaluated text coverage | Character errors / reference characters | Critical findings |
|---|---:|---:|---|
| `synthetic-bad/report.json` | 108 / 115 = 93.913% | 9 / 115 | 7 deleted non-whitespace characters, 2 affiliation edge errors, 2 symbol edits, 2 lost scripts, 1 missing section heading |
| `synthetic-good/report.json` | 115 / 115 = 100% | 0 / 115 | None in these synthetic fixtures |

The bad run exits 1 because it fails the 95% coverage gate; the good run exits 0.
`improvement/comparison.json` compares bad to good and reports no regression.
`regression/comparison.json` reverses that order and detects regressions (exit 1).
The CSV companions contain aggregate/article rows and localized differences.

Both sample XML families have `SCHEMA_UNAVAILABLE`. Even the good synthetic
candidate's exact match says nothing about publisher-schema acceptance.

Run IDs and evaluator source fingerprints are recorded inside each report.
Future evaluator changes require regenerating both sides into new report
directories before comparison. See [the complete guide](../scientific_qa.md).
