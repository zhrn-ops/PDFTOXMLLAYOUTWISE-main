## State lifecycle

1. `_load_pdf_path` starts `_PdfLoadWorker`; extraction, classification and refinement run in a QThread. GUI extraction explicitly disables Docling. The result contains a Document, display payloads and first-page raster. `_on_pdf_load_complete` rejects stale document-generation results and resets article workflow state.
2. Manual role assignment, article membership/boundaries and accepted paragraph operations update Document blocks and metadata. Raw extraction blocks are retained separately. `_update_document_model` and `_document_for_segment` build article views; linked author results are retained by segment.
3. Finishing an article runs selected Qwen/GROBID enrichment through `_ArticleFinishWorker`, generates ANI XML **in memory**, opens the correction workspace and locks reviewed blocks. Legacy `run_auto_pipeline` and `_export_article_xml` can still write files directly.
4. Corrections live in a separate `XmlDocumentSession`, not directly in Document. Raw malformed edits keep the last valid tree, mark raw state invalid and block export. Structured edits normally invalidate the issue list. XML editor history supports undo/redo; converter history is separate.
5. `ArticleDrafts._retain_draft` stores XML, raw editor text, source/path/PDF, dirty state and history. Switching drafts reconstructs a session. `.jatsdraft` JSON stores articles and a workflow snapshot, written with a temporary file and `os.replace`.
6. Reopening an article unlocks blocks without deleting its XML draft. Regeneration compares against `generated_xml`; corrected drafts require a review decision. Rejection retains `pending_generated`; acceptance archives the previous draft under a revision key. Timestamp-only ANI changes are ignored for comparison.
7. Session validation is transient, not a persisted last-validated revision/hash/profile. Draft activation constructs a new session, invalidating validation. Export automatically checks the current session and atomically saves a copy; it records `exported_xml` separately and forbids overwriting an opened source XML.
8. Workspace reopening decodes models and retained XML; converter undo history is cleared. Closing prompts to save/discard/cancel unsaved workspace changes. Existing tests cover these important protections. Encoding and serializer defects identified in the audit still affect some transitions.

## Coverage and limits

Existing tests cover author/affiliation parsing, article segmentation and workflow, paragraph continuation, scientific scripts, RTL, visible PDF text, lazy rendering, draft retention/regeneration, XML editing, comments, source preservation and external-entity non-resolution. Generated PDF fixtures are used. The full list is in the inventory.

Not established: publisher conformance; a reviewed golden corpus of complete research articles; realistic large-document performance/peak memory; live GROBID/Docling/LLM integration; supported multi-version packaging; native close-during-worker safety; dependency vulnerability status. Restricted scratch directories and generated output were not exhaustively inspected. Broad static inspection and passing tests are not proof of scientific accuracy on arbitrary PDFs.
